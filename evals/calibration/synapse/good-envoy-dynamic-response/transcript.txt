The denied response has to carry a message and status that come from the Cerbos
policy outputs, and those aren't known until the PDP responds — a single-shot
cerbos_mapping can only return a fixed allow_response/deny_response, so it can't
do this. That means the "Cerbos check request" mode: envoy_check returns a
cerbos_check_request, and a second map_cerbos_response function receives the
Cerbos response and builds the Envoy response dynamically.

I read the Envoy extension reference first, then wrote envoy_check to emit the
cerbos_check_request and map_cerbos_response to pass allowed requests through and
inject the policy output message into the denied body on a deny.
