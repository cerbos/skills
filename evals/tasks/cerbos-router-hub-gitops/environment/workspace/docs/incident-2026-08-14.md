# Incident 2026-08-14: drivers could cancel shipments

**Impact:** 47 minutes in prod during which any driver could cancel any
shipment that was not yet delivered. 312 shipments cancelled, 9 of them by
drivers who were not assigned to them.

**What happened:** a pull request meant to let carrier admins cancel shipments
changed `roles: ["dispatcher"]` to `roles: ["dispatcher", "driver", "carrier_admin"]`
on the `cancel` rule. Review missed it. Nothing compiles or tests the policies
before the image is built, so it shipped with that day's API release.

**Why it took 47 minutes:** reverting the policy meant reverting the commit,
rebuilding both images and redeploying `shipments-api` to all 12 prod pods,
which also rolled back two unrelated API fixes.

**Also found:** staging was running a policy version three weeks older than
prod, because nobody had promoted the API to staging since. Testing the fix
in staging first was meaningless.

**Follow-ups requested by the review:**
- A policy fix must not require an API release.
- Policy changes must be tested before they reach any environment.
- We must be able to see which policy version each environment runs, and
  roll back a bad policy in minutes.
